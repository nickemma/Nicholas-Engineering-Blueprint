# Chapter 47 · Portfolio Standards & The Architecture Portfolio

**Why this chapter matters:** six strong systems still under-perform if presented poorly. This chapter is how the flagships become a portfolio that converts.

### 47.1 The architecture portfolio

Beyond the repos, maintain a dedicated architecture showcase (a section of the website + the flagships/ directory of the Blueprint repo) containing, for each system: the architecture diagram, the design doc, the tradeoffs, the threat model, and the benchmarks — the artifacts hiring managers actually read. This concentrated “thinking layer” is what distinguishes you from candidates who show only code.

### 47.2 The presentation checklist (per flagship)

- Diagram above the fold in the README; ≤90s demo video; live demo URL where feasible.
- The Meridian-Standard README anatomy (Chapter 15.2); links to DESIGN_DOC, TRADEOFFS, THREAT_MODEL, RUNBOOK, benchmarks.
- A one-paragraph “why this exists” in plain language — a non-specialist should grasp the point.
- Cross-links to the systems it connects with — the interconnection made navigable.

### 47.3 The portfolio-level narrative

The six systems are ordered and framed as one platform: an edge (EMBER), a data foundation (LATTICE, MERIDIAN), a platform (VEYRONIX), an AI serving layer (TESSERA), and a governance plane (SYNAPSE-AI). Presented together, they answer the only question that matters — “what kind of engineer is this?” — before a single interview.
