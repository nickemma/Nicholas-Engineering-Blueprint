# How to Read a Level

Every level follows the identical seventeen-section structure, so the handbook reads as one coherent course rather than six essays. The sections, and what each is for:

| Section | Purpose |
|---|---|
| Overview & why it matters | The one paragraph that justifies the weeks. |
| Objectives / Learning outcomes | What becomes true of you — checkable at exit. |
| Prerequisites | What the level assumes; what to shore up first. |
| Timeline | Week allocation and the internal rhythm. |
| Theory | The concepts, in build order. |
| Architecture concepts | The design-level ideas, above the code. |
| Hands-on labs | Small artifacts that build the muscle. |
| Assignments | Larger exercises that integrate the labs. |
| Production project | The flagship — specified to Part VI depth. |
| Books / Papers / Blogs / RFCs | The reading, in the six-source framework, tiered. |
| Open source tasks | The ladder stage active this level. |
| GitHub / Portfolio / Blog deliverables | What ships publicly. |
| Interview topics | What this level makes you able to answer. |
| Weekly schedule | The level applied to the Chapter 14 planner. |
| Exit criteria | The binary gate to the next level. |
| Reflection questions | The Chapter 7 prompts, level-specific. |

Full project specifications (functional/non-functional requirements, all diagrams, schema, API, threat model, CI/CD, scalability roadmap) live in **Part VI — Flagship Projects**. Here, each production project is specified richly enough to build from; Part VI is the organization-grade charter.
